If I had to map out what I think the phases of a project are...

1. See an inkling of a problem to solve, then explore the problem space in depth. User feedback if possible, explore edge cases, document status quo.
2. Within the problem space, there is inevitable sub-problems. Stack rank them by "value" to you/stakeholder/etc.
3. Brainstorm potential solutions, starting from the top of the stack. Think about end goal vs time-constrained solutions.
4. Decide as a team which problems should be solved first, and which solutions should be built to solve them. This depends on time constraints of course. The decision needs to be clear so that the team can focus on the right things.
5. Now that you've commited to building something, and you've got capacity budgeted, the work needs to be broken down and sequenced. Create a project in a task tracker so that progress can be reported async to stakeholders. Also, keep in mind how you will validate that your project is actually valuable: what metrics need to be collected before and after release?
6. Go execute, build the thing, report regularly on progress, communicate delays early.
7. Release and monitor metrics, respond quickly to new information.
